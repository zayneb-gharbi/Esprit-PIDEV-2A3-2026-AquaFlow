Ouvrir le site et tester tes trois tâches

Tu n’as pas besoin d’ouvrir tous les fichiers. Suis d’abord la partie 1, puis les trois tests ci-dessous. Les fichiers du groupe sont conservés et le site reprend leur template.

1. Ouvrir le site2. Fiche admin3. Google / Facebook4. Double authentificationEn cas de problème

État réel : le code et les tests automatisés sont fournis. Les connexions Google/Facebook utilisent tes identifiants d’application privés : elles ne sont réellement validées qu’après un essai dans ton navigateur. Aucun secret réel n’est inclus dans ce ZIP.

1. Ouvrir le site sur Windows

  1. Fais un clic droit sur le ZIP → Extraire tout. Travaille dans le dossier extrait.
  2. Ouvre le panneau XAMPP et clique sur Start à côté de MySQL. Il doit devenir vert. Le lanceur utilise PHP directement.
  3. Dans le dossier extrait, ouvre aquaflow_demo, puis amir.
  4. Double-clique sur DEMARRER_WINDOWS.bat. Garde la fenêtre noire ouverte : elle fait fonctionner le site.
  5. Un fichier texte s’ouvre avec les comptes de test. Copie l’email et le mot de passe du compte voulu. Ce fichier se retrouve dans amir/var/MES_COMPTES.txt.
  6. Ouvre le lien ci-dessous. Si le premier chargement est trop rapide, actualise la page après le démarrage du serveur.

Ouvrir AquaFlow

http://127.0.0.1:8000/amir/public/index.php

Résultat attendu : la page de connexion AquaFlow. Connecte-toi d’abord avec le compte citoyen du fichier texte : tu dois arriver sur son profil.

PHP 8.1 ou supérieur est nécessaire, avec pdo_mysql, openssl et curl. Le script cherche PHP dans C:\xampp\php\php.exe, puis dans le PATH. La base aquaflow_amir est créée automatiquement ; les données existantes sont conservées.

Si tu as déjà une installation, garde ton ancien config/local.php et le dossier var privé. Une mise à jour du code ne doit pas les effacer.

2. Tâche admin : consulter les détails d’un utilisateur

  1. Clique sur Se déconnecter, puis connecte-toi avec le compte administrateur de MES_COMPTES.txt.
  2. Ouvre Citoyens, puis clique sur Consulter sur une ligne.
  3. Vérifie le nom, l’email, le téléphone, l’adresse, le rôle, le statut et la date de création. Vérifie aussi l’état Google/Facebook et 2FA.
  4. Refais le test dans Plombiers.
  5. Copie l’adresse de la fiche. Déconnecte-toi, connecte-toi comme citoyen et colle cette adresse.

Résultat attendu : l’administrateur voit les fiches. Le citoyen et le plombier reçoivent un refus d’accès. Un visiteur sans connexion est renvoyé à la page de connexion. Aucun mot de passe ni secret n’est affiché dans la fiche.

3. Tâche utilisateur : Google et Facebook

Les boutons deviennent disponibles quand leurs identifiants sont renseignés. Un bouton actif prouve seulement que la configuration est renseignée ; il faut encore tester la connexion.

A. Configurer Google
  1. Ouvre Google Auth Platform → Clients, sélectionne ton projet AquaFlow et ouvre Client Web 1, déjà créé.
  2. Dans les URI de redirection autorisés, vérifie exactement cette adresse puis enregistre :
http://127.0.0.1:8000/amir/public/index.php?page=oauth_callback&provider=google
  1. Si tu as conservé le JSON contenant le secret lors de la création du client : double-clique sur IMPORTER_GOOGLE_WINDOWS.bat, glisse le JSON dans la fenêtre, puis appuie sur Entrée. L’import conserve les réglages de Facebook et de MySQL.
  2. Sinon, double-clique sur CONFIGURER_CONNEXIONS_WINDOWS.bat. Dans le fichier ouvert, renseigne google_id et google_secret entre les apostrophes, puis Ctrl+S. Google n’affiche le secret complet qu’à sa création ; s’il a été perdu, crée un nouveau secret avec la rotation du client et conserve-le immédiatement.
  3. Pour une démonstration à plusieurs comptes, utilise une audience Externe et ajoute les comptes de test si l’écran Google le demande. Garde les clés sur ton PC, hors du dépôt Git.

Si le JSON a une ancienne redirection, vérifie l’adresse dans Google et utilise la saisie manuelle. L’import exige la redirection exacte dans le JSON.

B. Configurer Facebook
  1. Ouvre Meta for Developers → Mes applications dans ton navigateur habituel et crée une application proposant Facebook Login. Le code utilise la connexion Facebook standard.
  2. Dans les réglages du cas d’utilisation Facebook Login, active la connexion OAuth Web si elle est proposée et vérifie les redirections autorisées.
  3. Pour la configuration locale actuelle, l’adresse de retour calculée par AquaFlow est :
http://127.0.0.1:8000/amir/public/index.php?page=oauth_callback&provider=facebook

Meta impose HTTPS pour les sites de connexion. Si sa console refuse cette adresse locale, il faut une adresse HTTPS acceptée : modifie alors base_url dans config/local.php, puis les redirections Google et Facebook avec cette même adresse. Ouvre aussi le site avec cette adresse. Le lanceur fourni sert uniquement le site local en HTTP ; il ne crée ni hébergement HTTPS ni certificat.

  1. Dans les paramètres de base Meta, relève l’App ID et l’App Secret.
  2. Ouvre CONFIGURER_CONNEXIONS_WINDOWS.bat, renseigne facebook_id et facebook_secret, puis Ctrl+S.
  3. En mode développement, le compte utilisé pour l’essai doit avoir un rôle autorisé dans l’application et accepter l’invitation éventuelle. Une connexion publique peut nécessiter d’autres démarches dans Meta.

La création de l’application Meta et la connexion réelle ne sont pas réalisées par le ZIP. Les vérifications humaines et l’accès au compte se font dans ton navigateur.

4. Tâche utilisateur : Google Authenticator

Cette tâche peut être testée tout de suite avec un compte local. Elle ne nécessite ni client Google Cloud ni application Facebook.

  1. Installe Google Authenticator sur ton téléphone. Active la date et l’heure automatiques sur le téléphone et le PC.
  2. Connecte-toi à AquaFlow, puis ouvre Sécurité → Configurer Google Authenticator. Fais-le dans les cinq minutes après connexion.
  3. Dans Google Authenticator : + → Saisir une clé de configuration. Nom : AquaFlow. Clé : celle affichée sur le site. Type : Basé sur l’heure.
  4. Sur AquaFlow, saisis le code à six chiffres du téléphone et clique sur Confirmer l’activation.
  5. Conserve les huit codes de secours dans un endroit privé. Ils sont affichés une seule fois.
  6. Déconnecte-toi puis reconnecte-toi. Attends le prochain code du téléphone si le précédent vient d’être accepté, puis saisis-le.

Résultat attendu : le profil ne s’ouvre qu’après la deuxième vérification. Le mot de passe seul, Google seul ou Facebook seul ne suffisent plus pour ce compte.

Test complémentaireRésultat attendu
Saisis volontairement un mauvais code.Le site refuse l’accès.
Utilise un code de secours, puis essaie de le réutiliser lors d’une autre connexion.Il fonctionne une seule fois.
Si un compte Google/Facebook est associé, connecte-toi avec lui après activation de la 2FA.Le code du téléphone est aussi demandé.
Après une connexion récente, va dans Sécurité, entre un nouveau code et clique sur Désactiver la double authentification.Le statut devient « Désactivée ». À la prochaine connexion, le deuxième code n’est plus demandé.

Après cinq tentatives sur une même étape de vérification, attends quinze minutes. Ne supprime pas var/cle.txt : cette clé permet de lire les secrets 2FA chiffrés en base.

5. Ce que tu peux expliquer au professeur

PartieRôle dans le projet
Modèlesmodels/UtilisateurPersistant.php et models/SecuriteUtilisateur.php lisent et enregistrent les données avec PDO. Les valeurs des formulaires sont passées aux requêtes préparées.
Contrôleurscontrollers/ traite les actions, les sessions, les autorisations, Google/Facebook et les codes de sécurité. Les requêtes SQL sont dans les modèles.
Vuesviews/ affiche les formulaires et les résultats dans le template du groupe. Les vues réutilisées du groupe sont conservées.
Point d’entréepublic/index.php charge l’application ; ApplicationController.php choisit l’action demandée.

La connexion locale sert à tester et à associer les comptes. Le changement de mot de passe, les emails de réinitialisation, les historiques et l’export Excel ne font pas partie de ces trois tâches.

Validation automatique : 140 contrôles réussis sous PHP 8.4.27 WebAssembly et SQLite temporaire. Les fournisseurs OAuth sont simulés dans ces tests. L’installation XAMPP/MySQL et les vrais comptes Google/Facebook restent à vérifier sur le PC de validation.

Les tests détaillés sont dans amir/docs/resultats-tests.json. Pour les relancer avec Node.js : ouvre un terminal dans amir/tests, puis exécute npm ci et npm test.

6. En cas de problème

Double-clique d’abord sur VERIFIER_WINDOWS.bat. Il vérifie PHP, les extensions, la base et la présence des réglages, sans afficher les secrets.

ProblèmeAction
« PHP introuvable » ou commande non reconnueVérifie que XAMPP est installé dans C:\xampp. S’il est ailleurs, adapte AMIR_PHP dans les lanceurs.
Installation impossible / base inaccessibleDémarre MySQL dans XAMPP. Si MySQL a un autre port ou un mot de passe, renseigne les paramètres db_* dans config/local.php.
Le navigateur n’ouvre pas AquaFlowExtrais le ZIP, relance le fichier BAT et garde sa fenêtre ouverte. Vérifie que le port 8000 n’est pas déjà utilisé.
Le navigateur affiche le code PHPOuvre l’adresse HTTP indiquée dans la partie 1, au lieu de double-cliquer sur un fichier PHP.
Bouton Google ou Facebook griséRenseigne les deux valeurs du fournisseur dans le fichier local, enregistre et actualise.
redirect_uri_mismatchCompare l’adresse indiquée par VERIFIER_WINDOWS.bat à celle enregistrée chez le fournisseur : protocole, nom d’hôte, port, chemin et paramètres doivent correspondre.
État de connexion expiré / invalideRepars du bouton AquaFlow, avec la même adresse et le même navigateur. Ne remplace pas 127.0.0.1 par localhost au milieu de la connexion.
Code Authenticator refuséVérifie l’heure automatique des deux appareils et le compte sélectionné dans le téléphone. Attends le code suivant si le précédent a déjà servi.
« Reconnecte-toi » pour une action sensibleDéconnecte-toi et reconnecte-toi, puis refais l’action dans les cinq minutes.
